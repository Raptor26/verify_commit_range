# Проверка диапазона коммитов

`verify_commit_range.py` проверяет, что каждый коммит диапазона Git собирается и проходит тесты, а не только последний коммит ветки. Это помогает контролировать реструктуризацию истории с помощью `rebase` и `squash`.

Для каждого коммита создаётся отдельный временный `git worktree`. Текущее рабочее дерево, незакоммиченные изменения и его каталог `build/` не затрагиваются.

## Требования

- Python 3.10 или новее;
- Git с поддержкой `git worktree`;
- CMake и CTest;
- Ninja;
- компилятор и остальные зависимости проверяемого проекта.

В проекте должен быть файл `CMakePresets.json` с выбранными пресетами. Сборочный каталог каждого пресета должен называться `build/<preset>`.

## Запуск

Команда запускается из корня проверяемого репозитория:

```bash
python3 /path/to/verify_commit_range/verify_commit_range.py main..HEAD \
    --preset host_unit_tests
```

Проверка нескольких конфигураций:

```bash
python3 /path/to/verify_commit_range/verify_commit_range.py main..HEAD \
    --preset host_unit_tests \
    --preset firmware_release
```

Запуск тестов после сборки каждого указанного пресета:

```bash
python3 /path/to/verify_commit_range/verify_commit_range.py main..HEAD \
    --preset host_unit_tests \
    --preset firmware_release \
    --with-tests
```

В примерах `/path/to/verify_commit_range` нужно заменить на фактический путь к каталогу инструмента, а имена пресетов — на имена из `CMakePresets.json` проверяемого проекта.

### Аргументы

- `range` — диапазон в синтаксисе `git rev-list`, например `main..HEAD`. Базовый коммит слева от `..` не проверяется. Коммиты обрабатываются от старого к новому.
- `--preset <name>` — обязательный пресет CMake для сборки. Аргумент можно повторять для проверки нескольких конфигураций.
- `--with-tests` — запускать CTest после сборки всех выбранных пресетов. Без этого аргумента выполняются только настройка и сборка.

Зависимости проверяемого проекта должны быть установлены до запуска. Проектные сценарии настройки окружения не вызываются автоматически.

## Результат и диагностика

Команды настройки, сборки и тестирования выводятся в консоль, а их полный вывод сохраняется в `_verify_logs/<preset>.log` внутри временного worktree.

После успешной проверки коммита его worktree удаляется. При ошибке проверка останавливается на первом проблемном коммите, выводятся последние строки журнала и путь к сохранённому worktree. После диагностики его можно удалить командой из отчёта:

```bash
git worktree remove --force /path/to/temporary/worktree
```

Код возврата `0` означает успешную проверку всех коммитов, `1` — ошибку окружения, Git, сборки или тестов.
